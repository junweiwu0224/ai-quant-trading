# 研究 + Paper 生产化设计规格

- 状态：Accepted
- 日期：2026-08-17
- 负责人：项目所有者
- 基于：[决策平台重构规格](2026-08-14-decision-platform-refactor.md)、[Vue 功能等价矩阵](2026-08-17-vue-feature-equivalence-matrix.md)
- 相关 ADR：[0005](../decisions/0005-vue-dashboard-migration.md)

## 1. 背景与目标

当前项目已完成决策域、独立 Worker、冻结报告、资格门禁和 Vue 主流程实现。本规格定义将系统推向**研究 + Paper 生产**的完整设计，包括：

1. 六市场真实分级数据能力（A股/港股/美股/日股/韩股/台股）
2. 完整 More 功能入口迁移
3. 单股研究体验优化
4. AI 工作台（证据决策链）
5. Token 用量可观测
6. 整体 UI/UX 提升（宽松现代风格）

**生产定义**：个人单机 Docker 部署、单 workspace、可复现决策、受控通知和模拟盘；真实券商/实盘保持硬禁用。

## 2. 非目标

- 多用户/多租户/公网 SaaS
- 真实券商 SDK 接入或实盘自动下单
- 六市场全部实时/盘中数据（按 adapter 能力分级）
- 完整替代参考项目的所有功能（只吸收已验证的工作流）

## 3. 整体架构与路由

### 3.1 技术栈

**保持不变**：
- Vue 3 + TypeScript + Vite
- Pinia (状态管理)
- Vue Router (history mode)
- FastAPI 同源托管 `/app/*`

### 3.2 主路由结构

```
/app (Vue Shell)
  ├─ /decision          # 决策中心
  ├─ /reports           # 报告索引
  ├─ /research/:market/:symbol  # 单股研究
  ├─ /validation        # 验证页
  ├─ /notifications     # 通知配置
  ├─ /settings          # 设置
  └─ /more              # 更多工具
```

### 3.3 布局组件

**选择：侧栏 + 主区域布局**

```
AppShell.vue (根容器)
├─ Sidebar.vue (桌面左侧导航，240px 固定宽)
├─ MobileNav.vue (移动底部导航，64px 固定高)
└─ MainContent.vue (flex-1，带内边距和最大宽度约束)
    └─ <router-view>
```

**桌面侧栏内容**：
- Logo + workspace 选择器
- 主导航：决策中心、研究、验证、报告、通知、设置、更多
- 底部：Token 用量摘要、主题切换、账户

**移动底栏**（4 个核心入口）：
- 决策、研究、报告、更多

**权衡**：
- 侧栏固定宽度：减少布局漂移，桌面空间充足
- 移动 4 入口：避免拥挤，次要功能通过"更多"进入
- 不使用全屏模态路由：保持浏览器前进/后退可用

## 4. 单股研究页设计

### 4.1 路由与 Tab

**路由**：`/app/research/:market/:symbol`

**选择：Tab + 面板**

**Tab 结构**（顶部水平 Tab 栏）：
1. **K线与技术** — K线图、指标、画线工具、多周期切换
2. **证据与决策** — 数据质量、策略贡献、确定性动作、AI 解释、历史决策
3. **回测草案** — 单股回测、参数调优、Monte Carlo

### 4.2 K线与技术 Tab 布局

```
┌─────────────────────────────────────────┐
│ 工具栏：周期选择 | 指标 | 画线 | 对比   │
├─────────────────────────────────────────┤
│                                         │
│           K线图主区域                    │
│         (占据大部分高度)                 │
│                                         │
├─────────────────────────────────────────┤
│ 五档/分时/成交明细 (可切换的底部面板)    │
└─────────────────────────────────────────┘
```

**K线图组件**：
- 复用现有 K线渲染逻辑
- 周期：1m/5m/15m/30m/60m/日/周/月
- 指标叠加：MA/EMA/BOLL/MACD/RSI/KDJ
- 画线工具：趋势线/水平线/斐波那契，支持保存/加载

### 4.3 证据与决策 Tab 布局

**选择：上下文证据链（纵向时间线）**

```
┌─────────────────────────────────────────┐
│ 1. 输入快照卡片                          │
│    数据来源 | 更新时间 | 覆盖率 | 质量   │
├─────────────────────────────────────────┤
│ 2. 策略贡献列表（可展开卡片）            │
│    ┌─ 策略A: 75分 (权重30% × 信心0.9)   │
│    │  数据质量: 0.95 | 原因码: ...      │
│    └─ [展开查看详细因子]                │
│    ┌─ 策略B: 82分 (权重40% × 信心0.85) │
│    └─ ...                               │
├─────────────────────────────────────────┤
│ 3. 确定性动作卡片                        │
│    综合分: 78 → 买入候选                │
│    状态历史时间线                        │
├─────────────────────────────────────────┤
│ 4. AI 解释（可选，浅色背景区分）         │
│    [等待生成] 或 [已生成的解释文本]     │
└─────────────────────────────────────────┘
```

**AI 工作台原则**：
- 冻结输入 → 策略贡献 → 确定性动作 → AI 解释（可选）
- AI 只解释，不改变动作或分数
- 用浅色背景区分 AI 内容与确定性决策
- AI 不可用时不影响决策展示

### 4.4 回测草案 Tab

**布局**：
- 上方：参数表单（日期范围、初始资金、策略选择）
- 运行按钮 → 结果展示（收益曲线、回撤、指标卡片）
- 保存到验证页的入口

### 4.5 移动端适配

- Tab 栏保持水平滚动
- K线图高度固定 400px（避免滚动嵌套）
- 证据卡片纵向堆叠，可展开/折叠
- 回测结果使用可横向滑动的图表容器

## 5. 视觉规范与组件系统

### 5.1 风格选择

**宽松现代风格**：大间距、圆角卡片、流畅过渡动效

### 5.2 间距系统

```
xs: 4px   | sm: 8px  | md: 16px
lg: 24px  | xl: 32px | 2xl: 48px

卡片内边距：lg (24px)
卡片间距：md (16px)
章节间距：xl (32px)
```

### 5.3 圆角

- 小组件（按钮、标签）：`6px`
- 卡片：`12px`
- 模态框：`16px`

### 5.4 色彩方案

**浅色主题**：
```
背景：#f9fafb (gray-50)
卡片：#ffffff
文本主：#111827 (gray-900)
文本次：#6b7280 (gray-500)
边框：#e5e7eb (gray-200)
主色：#16a34a (green-600) — 决策/买入
警告：#dc2626 (red-600) — 风险/卖出
信息：#2563eb (blue-600) — 中性状态
```

**深色主题**：
```
背景：#111827 (gray-900)
卡片：#1f2937 (gray-800)
文本主：#f9fafb (gray-50)
文本次：#9ca3af (gray-400)
边框：#374151 (gray-700)
主色/警告/信息使用稍亮变体
```

### 5.5 动效规范

**时长**：
- 快速交互：`150ms`
- 页面切换/模态：`300ms`

**缓动**：`cubic-bezier(0.4, 0, 0.2, 1)` (ease-in-out)

**应用场景**：
- 卡片悬停：`translateY(-2px)` + box-shadow 加深
- Tab 切换：淡入淡出 + 轻微位移
- 列表项加载：交错淡入 (stagger 50ms)
- 数据刷新：骨架屏淡出 → 真实内容淡入

### 5.6 核心组件库

```
BaseCard.vue           # 统一卡片容器
BaseButton.vue         # 主要/次要/危险/文本按钮
BaseInput.vue          # 表单输入
BaseSelect.vue         # 下拉选择
BaseTabs.vue          # Tab 切换器
BaseTag.vue           # 状态标签
DataQualityBadge.vue  # 数据质量指示器
StrategyCard.vue      # 策略贡献卡片
DecisionTimeline.vue  # 决策历史时间线
```

### 5.7 字体

- 西文：`-apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`
- 中文：`"PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`
- 等宽（代码/数字）：`"SF Mono", Monaco, Menlo, Consolas, monospace`
- 基础字号：`15px` (桌面) | `14px` (移动)

### 5.8 "去 AI 感"原则

- 不用渐变背景、霓虹色、科技感蓝紫
- AI 解释用朴素文本块，不加对话气泡或头像
- 避免"智能推荐"、"AI 为您分析"等营销式文案
- 数据来源明确标注，不用"系统检测到"等模糊表述

## 6. 数据流与状态管理

### 6.1 Pinia Store 结构

```typescript
stores/
├─ app.ts              # 全局：主题、侧栏状态、Toast 通知
├─ auth.ts             # 认证：当前用户、workspace、权限
├─ decision.ts         # 决策：组合列表、当前选中、状态变化流
├─ research.ts         # 研究：当前股票、K线数据、指标配置
├─ validation.ts       # 验证：策略验证结果、权重候选
├─ reports.ts          # 报告：报告索引、筛选、投递历史
└─ market.ts           # 市场：市场列表、能力声明、数据健康
```

### 6.2 API Client 组织

```typescript
api/
├─ client.ts           # 基础 fetch 封装、错误处理、API Key 注入
├─ decisions.ts        # 决策相关端点
├─ research.ts         # 单股研究端点
├─ validation.ts       # 验证端点
├─ reports.ts          # 报告端点
├─ notifications.ts    # 通知配置端点
└─ types.ts            # 共享 TypeScript 类型
```

### 6.3 关键数据流

**决策中心加载**：
```
用户进入 /app/decision
  → decision store 加载组合列表
  → 并行请求每个组合的最新状态
  → 渲染组合卡片（状态、数据健康、下次运行时间）
  → WebSocket 订阅状态变化推送
```

**单股研究加载**：
```
路由到 /app/research/:market/:symbol
  → research store 初始化
  → 并行请求：
     - K线数据（当前周期）
     - 最新决策（如果存在）
     - 数据质量状态
  → 渲染 K线 Tab（默认）
  → 切换到证据 Tab → 请求策略贡献详情
  → 触发 AI 解释 → 后台请求，加载态显示
```

**数据预览触发**：
```
验证页点击"预览"
  → POST /api/decisions/preview
  → 后端冻结输入快照、运行策略、生成报告
  → 返回 run_id 和初始状态
  → 前端轮询或 WebSocket 监听完成
  → 跳转到报告详情页
```

### 6.4 WebSocket 使用

- `/ws/decision-updates`：订阅组合状态变化、数据刷新通知
- `/ws/quotes`：K线实时行情（独立）
- 连接断开后降级为定时轮询（30秒间隔）

### 6.5 本地缓存策略

- K线数据：IndexedDB 缓存，7天过期
- 用户偏好（主题、图表配置）：localStorage
- 敏感数据（API Key）：sessionStorage，刷新后重新输入
- 不缓存决策、报告内容（始终从服务端获取最新）

### 6.6 错误处理

- API 错误：Toast 通知 + 错误边界组件兜底
- 网络超时：显示重试按钮，保留用户输入
- 数据缺失：显式"数据不可用"占位，附原因（而非空白或 0）
- Token 用量超限：前端预警 + 后端硬限制

## 7. 六市场数据能力

### 7.1 MarketAdapter 契约

每个市场必须声明：
- 市场代码、时区、交易所日历
- 支持的数据粒度（日线/5分钟/Tick）
- 数据源（当前/目标）
- 自动推送能力
- 数据质量指标（来源、更新时间、覆盖率）

### 7.2 六市场分级策略

| 市场 | 初始状态 | 当前数据源 | 目标数据源 | 自动推送 |
|------|---------|-----------|-----------|---------|
| A股  | 默认可配置 | mootdx/腾讯/东方财富 | Tushare Pro/TickFlow | 资格通过后允许 |
| 港股 | 用户开启 | 待接入 | Longbridge | adapter 完成后允许 |
| 美股 | 用户开启 | 待接入 | Longbridge | adapter 完成后允许 |
| 日股 | 用户开启 | YFinance（日线） | 待评估 | 仅手动/定时日线 |
| 韩股 | 用户开启 | YFinance（日线） | 待评估 | 仅手动/定时日线 |
| 台股 | 用户开启 | YFinance（日线） | 待评估 | 仅手动/定时日线 |

### 7.3 数据质量显示

**必须显示**（至少两项）：
- 数据来源（provider 名称）
- 更新时间（绝对时间或相对时间）
- 覆盖率（百分比或成员数）

**数据缺失时**：
- 显式"数据不可用"占位
- 附原因（provider 离线、未配置凭证、市场闭市等）
- 不用 0、空白图表或模拟数值掩盖

## 9. Token 用量可观测

### 9.1 展示位置

**侧栏底部摘要**（桌面）：
- 当前会话用量：`12.5K / 200K`
- 点击展开详情抽屉

**详情抽屉内容**：
- 总用量条形图
- 按功能分组：研究、决策、AI 解释、Agent
- 最近 10 次 API 调用列表（时间、功能、用量）
- 清空会话按钮

**移动端**：
- 设置页中显示完整 Token 用量面板
- 侧栏无空间，不展示摘要

### 9.2 用量追踪

- 前端请求时记录功能标签
- 后端响应头返回 Token 用量
- 前端累加到 Pinia store
- 刷新页面时用量重置（sessionStorage 可选保留）

## 13. 与现有规格的关系

本规格**补充**而非替代 [决策平台重构规格](2026-08-14-decision-platform-refactor.md)：

- 决策域、Worker、报告、Outbox、备份恢复：已完成，保持不变

- More 功能迁移：本规格补充迁移矩阵

两份规格共同构成生产化的完整蓝图。
