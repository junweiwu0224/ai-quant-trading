# 决策与自动报告平台重构规格

- 状态：Accepted
- 日期：2026-08-14
- 负责人：项目所有者
- 取代：[DSA 能力选择性吸收规格](2026-08-13-dsa-capability-absorption.md)
- 相关 ADR：[0004](../decisions/0004-decision-worker-and-immutable-artifacts.md)、[0005](../decisions/0005-vue-dashboard-migration.md)、[0006](../decisions/0006-market-adapter-and-auto-push-eligibility.md)

## 1. 背景

系统已具备行情、因子、单股研究、策略、回测、模拟盘、Agent、日报和通知等许多能力，
但这些能力没有形成日常可执行的闭环。用户不能自然地从自选池获得可验证的组合决策，
也不能只在有意义的状态变化时收到可追溯的简洁通知。当前 Jinja2/Vanilla 前端的导航和
状态边界又放大了这个问题。

本次重构的产品闭环是：

```text
自选池 -> 策略组合 -> 数据预览 -> 历史验证 -> 确定性决策
       -> AI 解释 -> 冻结报告 -> Outbox -> 多渠道摘要 + 完整报告链接
```

现状边界必须如实保留：当前实时/历史数据主路径仍是 A 股的 mootdx、腾讯和东方财富；
当前 `dashboard` 进程拥有 APScheduler 和通知 consumer；当前通知只有通用 Webhook/
DailyBrief adapter；当前没有 Vue/Vite 工程或独立 Worker。目标数据源和目标运行拓扑不是
已经完成的能力。

## 2. 目标

1. 让用户以策略组合为单位管理自选股，并能对任意单股或组合做即时、只读的手动分析。
2. 对每个组合产生可复现的五档确定性决策；AI 只解释，不修改动作。
3. 在每日 `09:00`、`12:30` 发送准备好的组合摘要；盘中仅在确认的状态变化或首次重大风险
   时立即推送。
4. 将长报告迁移到独立、适合手机和桌面阅读的只读页面，消息渠道只发送精简摘要和链接。
5. 用数据预览、滚动样本外验证、运行健康和渠道测试约束自动推送，不让缺失数据自动化。
6. 完整迁移 Dashboard 前端体验到 Vue，而不牺牲当前研究、回测、模拟盘和高级工具。
7. 将运行、输入、权重、AI、报告和投递永久保留，使一份已发送结论能够复现与审计。

## 3. 非目标

- 本阶段不执行真实下单、不接券商凭证、不开放无人工确认的实盘路径。
- 不把 AI 建议的后验收益、策略回测净值和真实/模拟盘绩效混为一个指标。
- 不承诺未接入或未验证 provider 的实时行情、5 分钟信号或跨市场自动推送。
- 不复制竞品的 UI、数据库、代码或许可受限资产；仅吸收已确认的产品能力和工作流。
- 不把所有数据放入一张通用表，也不建立会绕过现有回测和风险边界的第二套交易引擎。
- 不在本规格阶段启动 Docker、外部数据同步、外部 LLM、真实 Webhook 或任何交易脚本。

## 4. 用户、范围和工作流

### 4.1 用户与范围

- 当前主体是当前 workspace 的个人研究者；所有组合、自选、通知目标、报告和链接都必须
  受 workspace 隔离。
- A 股默认可配置；港股、美股、日股、韩股、台股可在市场选择器启用，但能力由对应
  `MarketAdapter` 声明，不能把“已显示”误表述为“可自动推送”。
- 一个标的可以属于多个策略组合。组合各自计算、验证、报告和通知，互不覆盖。

### 4.2 三条主流程

```text
手动研究：股票/组合 -> 选择已验证版本 -> 冻结输入 -> 确定性决策 -> AI 解释 -> 报告

定时报告：交易时段前 30 分钟准备 -> 09:00 / 12:30 -> 组合摘要 -> 路由 -> 投递记录

盘中信号：完成 5 分钟 K 线 -> 两根确认 -> 状态变化 -> 立即摘要 -> 完整报告链接
                                      \-> 首次重大风险：不等待确认，立即推送
```

手动研究不改变自动动作、策略权重、自动推送资格或下一次定时任务；它只生成新的、带有
`manual` 触发来源的只读决策和报告。

## 5. 领域模型与不可变性

### 5.1 主要实体

| 实体 | 职责 | 不变量 |
| --- | --- | --- |
| `StrategyPortfolio` | 当前 workspace 中一个市场的组合身份、名称、启停状态与日程 | 不等同于真实持仓；每个组合只属于一个市场 |
| `PortfolioMembership` | 标的加入组合的可变关系 | `(portfolio_id, instrument_id)` 唯一；同一标的可在多个组合 |
| `PortfolioVersion` | 策略选择、权重、阈值、风险否决规则、成本/验证配置的冻结快照 | 已被运行引用后永不修改；配置变更只创建新版本 |
| `StrategyWeight` | 一个版本内某策略的启用状态、权重与角色 | 非风险否决权重归一化为 1；风险否决策略不参与加权平均 |
| `DecisionInputSnapshot` | 行情、指标、证据、成员、数据质量、provider 与版本引用 | 内容哈希固定；不得在运行中重新抓取未记录数据 |
| `DecisionRun` | 对一个组合版本和输入快照的计算记录 | `run_key` 全局唯一且幂等；保存触发来源和结果状态 |
| `Decision` | 一个成员在一次运行中的动作、分数、贡献、原因码与质量 | `(decision_run_id, membership_id)` 唯一；生成后不可修改 |
| `DecisionReport` | 决策的确定性报告正文、附件和内容哈希 | 只追加；不允许 AI 改写动作或正文事实 |
| `AICommentary` | AI 对已生成决定的解释补充件 | 关联模型、prompt、输入哈希与输出；不得参与状态机 |
| `NotificationTarget` | 频道和接收目标的配置、健康与密钥引用 | 仅存密钥引用，不存或输出明文凭证 |
| `NotificationRoute` | 组合/事件类型到目标的路由 | 可多目标；只影响投递，不影响决策 |
| `DeliveryAttempt` | 每次外部投递的结果 | 只追加；同一幂等键最多一次成功投递 |
| `ReportShareLink` | 报告聚合页的不可猜测访问令牌 | 数据库只存 token 哈希；7 天失效且可撤销 |

`DecisionReport` 是确定性核心，`AICommentary` 是独立不可变补充件。盘中通知不能等待
AI：它立即链接确定性报告；AI 就绪后报告页在同一个决策下展示已签名的补充件，不覆盖或
修改原报告。这样“立即动作”和“AI 汇总”不会互相阻塞。

### 5.2 评分、权重和动作

每个策略输出统一契约：`normalized_score`（0-100）、`confidence`（0-1）、`data_quality`
（0-1）、`reason_codes[]`、`strategy_version` 和可选 `risk_veto`。非风险否决策略的贡献为：

```text
effective_weight = configured_weight * confidence * data_quality
composite_score = clamp(0, 100, sum(normalized_score * effective_weight) / sum(effective_weight))
```

`configured_weight` 是版本中非风险否决策略的归一化权重；`effective_weight` 与贡献均须保存
到 `Decision`。若分母为零，结果为 `invalid` 而不是伪造 0 分；当任何必需数据失效时，系统
沿用最近的有效状态并标记数据过期，不产生新动作。

默认动作和初始进入边界：

| 动作 | 分数区间 | 说明 |
| --- | --- | --- |
| 买入候选 | `>= 70` | 通过验证的高分候选，不是订单 |
| 关注 | `55 <= score < 70` | 需要持续跟踪 |
| 观望 | `40 <= score < 55` | 无明确方向优势 |
| 减仓候选 | `score < 40` | 负向倾向，不产生实际卖单 |
| 重大风险 | 风险否决命中 | 覆盖任何分数和普通状态 |

为避免边界抖动，普通动作采用 5 分滞回：`买入候选 -> 关注` 低于 65；`关注 -> 买入候选`
不低于 75；`关注 -> 观望` 低于 50；`观望 -> 关注` 不低于 60；`观望 -> 减仓候选` 低于
35；`减仓候选 -> 观望` 不低于 45。普通状态一次只跨一个等级；重大风险可直接覆盖。

### 5.3 确认、去重和数据失效

- 普通盘中变化须由连续两根**完成**的 5 分钟 K 线得到同一目标动作确认。未完成、缺失、
  乱序或被 provider 标为修订中的 bar 不计数。
- 组合成员首次建立的普通状态只留审计记录，不推送；首次重大风险立即推送，且不受静默
  期限制。风险持续或重复运行不重复推送。
- 变化去重键为 `portfolio_id + membership_id + action + confirming_bar_end + portfolio_version_id`；
  定时摘要去重键为 `portfolio_id + schedule_slot + trade_date + portfolio_version_id`；路由投递
  再追加 `target_id`。所有 key 在存储层唯一。
- 当前数据不新鲜、覆盖不足或关键字段缺失时，记录 `stale/invalid` 原因并保留最近有效
  状态。若下一交易日仍未恢复，状态转为 `decision_invalid`，自动推送资格暂停，直到新的
  预览和有效运行恢复。重大风险只可由仍有效的风险输入立即触发。

## 6. 验证、回测和权重优化

### 6.1 自动推送资格

每个 `(workspace, market, strategy_portfolio, portfolio_version)` 独立计算资格。只有同时满足
以下条件才可打开自动推送开关：

1. 当前版本至少有一个启用成员和一个启用策略，且存在成功的“预览报告”。预览必须使用
   最新合格数据真正运行一次，显示每个成员的动作、来源、更新时间、覆盖率和缺失字段；
   空结果、mock 或仅 schema 通过都不合格。
2. 每个启用策略均有满足其输入契约的有效数据；市场 adapter 声明支持该粒度和触发方式。
3. 当前版本通过本节规定的历史验证，且未因数据失效、版本撤销或 market adapter 降级而
   失效。
4. 每个启用通知目标完成独立测试投递并处于健康、启用状态。

未取得资格的市场/组合仍允许手动分析和手动报告，UI 必须显示阻断原因，不提供可绕过的
自动开关。

### 6.2 回测口径

- 自动推送版本至少使用 4.5 年可用历史，采用 `24 个月训练 + 6 个月样本外` 的 walk-forward
  验证，每 6 个月滚动一次，至少 3 个独立样本外窗口。
- 信号只可使用决策时点已知的数据。日线收盘信号在下一可交易时段开盘成交；完成的 5 分钟
  信号在下一根可交易 bar 开盘成交。停牌、涨跌停、缺失报价或市场闭市导致无法成交时，
  按对应 `MarketAdapter` 的可交易性规则延后，不得假设即时成交。
- 每个回测保存市场日历、标的存续池、复权/公司行动版本、基准总回报、费用滑点模型、
  再平衡、现金和失败订单规则。退市标的必须保留到可得的最后价格并按明确的退市处理规则
  结算，禁止只用今天仍上市的股票池产生幸存者偏差。
- 年化收益按 `(ending_nav / starting_nav) ** (252 / trading_days) - 1` 计算；所有市场使用
  其 adapter 的实际交易日数替换 252。基准使用同日期、同币种、含公司行动的总回报序列。
- 成本、滑点和集中度不是隐含常数：它们必须由 `ExecutionCostModelVersion` 固定。默认 A 股
  成本模型应以用户券商费率为准；未配置时只能标为“通用假设”，不能作为实盘收益承诺。

### 6.3 候选权重与生效

- 每个市场最后一个交易日收盘后运行优化；候选只能在下一个交易时段生效，绝不在盘中
  改写当前版本。
- 确定性优化器和 LLM 都可以提出候选权重；LLM 输出必须被解析为同一受限 schema，失败或
  不合法时丢弃候选，而非降级为自由文本决策。
- 候选必须在相同冻结样本上相对当前版本的样本外年化收益至少提高 2 个百分点，并满足：
  样本外最大回撤不超过 25%、年化换手不超过 12 倍、单标的最大目标权重不超过 20%。这些
  是候选策略回测组合的风控红线，不是 `StrategyPortfolio` 内信号权重的限制；红线由版本化
  验证配置保存，未来调整必须创建新版本并重新验证。
- 通过硬门槛的候选按样本外年化收益降序、最大回撤升序、年化换手升序、候选内容哈希升序
  排名；完全并列则保留当前版本。这取代“LLM 候选优先”，保证同一输入必得同一生效版本。

## 7. 数据与多市场能力

### 7.1 MarketAdapter 契约

每个 adapter 至少声明：市场代码、时区、交易所日历、标的标准化规则、币种、最小价格
精度、日线和盘中粒度、复权/公司行动方式、基准、成本模型、支持的报告类型、数据源和
自动推送能力。每个报告及 UI 视图必须暴露这些能力及其 `source`、`updated_at`、
`coverage_pct`、`stale`、`fallback_reason`。

| 市场 | 初始状态 | 目标主源 | 允许自动推送 |
| --- | --- | --- | --- |
| A 股 | 默认可配置 | Tushare Pro（历史/回测）、TickFlow（完成 5 分钟 K 线） | 在逐组合资格通过后允许 |
| 港股、美股 | 用户开启后可配置 | Longbridge | 在 adapter、验证和资格通过后允许 |
| 日股、韩股、台股 | 用户开启后仅研究 | YFinance 可用于手动研究/定时日线 | 不允许 5 分钟自动信号，直到合格 provider 接入 |

接入任何目标 source 需要单独的凭证、费用、速率、断路器、缓存、数据许可证和回归测试
工作；本规格不授权调用或保存其凭证。

### 7.2 数据质量规则

- 数据预览和运行必须记录必要字段、每字段来源、时间、缓存年龄、覆盖范围、失败原因和
  provider health；没有数据时返回“不可判断”，不能补 0 或沿用未标记缓存。
- 回测、定时报告和盘中信号各自声明对日线/5 分钟、复权和 freshness 的最低要求；一个
  source 的健康不能替代另一个 source 的资格。
- 本地当前 mootdx/腾讯/东方财富数据在目标 provider 未接入前可以继续提供手动研究和既有
  功能，但新 UI 不得把它标为已经满足目标的多市场盘中自动化。

## 8. Worker、调度、通知和报告

### 8.1 执行拓扑

目标本机 Compose 拓扑为 `dashboard + worker + cloudflared`。Mac 登录后启动该 Compose；
`dashboard` 托管控制面、查询 API 和 Vue 构建，`worker` 是唯一调度/计算/Outbox consumer，
`cloudflared` 仅暴露受控 HTTPS 域名。不开放家庭路由器端口。

`app.<domain>` 指向 Dashboard，`report.<domain>` 指向只读报告页。没有服务器不阻碍推送：
只要本机保持开机、Docker 服务与出站网络可用，Worker 可以按计划调用外部渠道；关机或
断网期间任务会延迟并由幂等恢复处理，不能声称它们已经按时发送。

### 8.2 调度规则

- 每个交易日的 `09:00`、`12:30` 是发送时点；Worker 分别在 `08:30`、`12:00` 开始准备。
  准备完成只生成冻结候选，不得提前投递。
- 市场日历、时区和午休由 MarketAdapter 决定。非交易日不生成伪日报；可选周末复盘必须
  是另一个明确的日程与报告类型。
- 盘中 signal worker 对完成 5 分钟 K 线运行确认逻辑。排队、执行、恢复、手动触发均写入
  `DecisionRun`，同一幂等键只能有一个成功结果。
- Dashboard 重启不会启动第二个调度器；Worker lease、Outbox claim token 和运行唯一约束共同
  阻止双执行。

### 8.3 通知与投递

支持企业微信机器人、PushPlus 个人微信服务、飞书群机器人、QQ 官方机器人。每个组合可
配置多个 route 和多个 target；目标有独立启用、测试、失败计数、禁用和重试状态。

- 摘要最多列出 10 个变化或风险。无变化时仅发送组合总览、数据状态和完整报告链接。
- 常规变化与定时报告遵循 route 的静默/去重策略；首次重大风险强制发送并记录为何绕过
  静默限制。
- 外部请求只由 Outbox consumer 发送。投递采用有限指数退避，默认最多 5 次；最终失败进入
  dead 状态并在 Dashboard 可见。通知失败永不回滚决策或报告。
- 目标凭证通过环境变量、系统密钥链或受保护 secret reference 注入；数据库、日志、报告和
  API 响应只保留脱敏标识与 hash。

### 8.4 报告与外链

完整报告是独立路由，不嵌在微信、飞书或 QQ 文本中。它首先为手机窄屏排版，同时提供
桌面双栏/宽表布局。报告页展示：组合和市场、动作变化、综合分及贡献、策略/权重版本、
数据质量、关键证据、风险否决、AI 解释状态、验证摘要、输入/报告 hash 和投递历史。

`ReportShareLink` 为 256 bit 随机 token，数据库只存 SHA-256 hash；默认 7 天失效、可单独
撤销、不要求登录。链接可访问报告聚合页和其固定的不可变工件，不能访问 workspace 的
其它报告或 API。

## 9. 存储、备份、恢复与保留

### 9.1 多数据库边界

保留现有行情/账户/Agentic 数据库的职责，不把历史行情复制为新的 decision 表。新增的
决策域 SQLite 数据库保存组合、版本、运行、快照索引、决策、报告索引、路由和投递；
大体积原始 payload、报告附件和证据正文以内容哈希命名的不可变文件存储，并由数据库
记录路径和 hash。

所有引用必须能从 `Decision` 反向追溯到版本、输入、证据、AI 补充件、报告和投递，且
不能依赖可变的“当前配置”。输入中引用的市场原始数据保留的是 provider、请求/响应 hash、
收集时刻和标准化序列；其可重放副本的保存期必须至少覆盖引用它的审计工件，不能把短期
行情缓存清理后仍宣称该决策可复现。

### 9.2 备份与恢复

- 每日进行一次本地一致性备份，不设置报告、日志或附件的数据量硬上限；Dashboard 展示
  数据库、报告、证据、日志的当前用量和趋势。
- SQLite 的跨文件备份采用 Worker 写入屏障：暂停新运行与 Outbox claim、等待已有事务到达
  安全点、对每个数据库执行 SQLite online backup、复制内容寻址附件、生成包含版本、hash、
  时间和文件清单的 `BackupManifest`，最后解除屏障。不得把简单文件复制描述为一致性备份。
- 每月至少一次从最近备份恢复到隔离目录，校验 manifest、外键/引用、内容 hash，并抽样按
  指定 `decision_id` 重放生成的确定性报告。恢复演练不连接外部通知或市场 provider。
- 决策、报告、输入快照、版本、AI 工件和投递记录永久保存。删除/压缩只能处理非审计性
  可再生缓存，且不能破坏任何已保存 hash 链。

## 10. Vue 前端重构

### 10.1 技术和路由

新前端放在 `dashboard/ui/`，使用 Vue 3、TypeScript、Vite、Vue Router history 模式、Pinia
和类型化 API client。生产构建由 FastAPI 在 `/app/*` 同源托管；开发阶段 Vite 代理 `/api`
和 WebSocket。既有 Jinja 静态资源与 `/app/assets/*` 分开，避免路径覆盖。

主路由：

| 路由 | 体验职责 |
| --- | --- |
| `/app/decision` | 决策中心：市场切换、组合、状态变化、数据健康和下一次运行 |
| `/app/reports` | 独立报告索引、筛选、投递状态、导出证据包 |
| `/app/research/:market/:symbol` | 单股研究：K 线、指标、证据、决策、回测草案和来源上下文 |
| `/app/validation` | 策略/组合验证、walk-forward、权重候选、资格阻断原因 |
| `/app/notifications` | 目标、route、测试、失败队列和发送历史 |
| `/app/settings` | 市场、策略组合、版本、数据源和保留设置 |
| `/app/more/*` | 模拟盘、因子研究、AI Alpha、Agent、AI Runtime、Broker/实盘只读入口等高级工具 |

桌面采用左侧导航，移动采用底部导航。研究和回测在移动端使用可切换工作区、抽屉和横向
数据查看，不以“移动端不支持”隐藏核心能力。

### 10.2 功能迁移矩阵

| 当前能力 | 新入口 | 迁移完成条件 |
| --- | --- | --- |
| 总览、市场雷达、自选、预警、机会池 | 决策中心 | 可按市场和组合筛选；保留来源、覆盖与健康状态 |
| 股票详情、K 线、指标、画线、多股对比 | 单股研究 | 原有周期、指标、证据与来源上下文可用 |
| 策略、策略版本、回测、优化、PDF | 验证/回测 | 旧 API 兼容，新旧关键数值契约一致 |
| Alpha、因子、选股、Walk-Forward | 验证/回测或更多 | 每个旧入口有可发现的新路由，不能只保留 API |
| 模拟盘、持仓、风控、条件单 | 更多与决策中心关联 | 现有安全禁用和人工确认不退化 |
| AI 助手、Agent、AI Runtime、研究日报 | 更多与报告 | workspace 隔离、任务状态与历史可查 |
| Broker、实盘设置 | 设置/更多 | 未配券商时保持显式禁用，不能产生真实下单 |

旧路径的 query URL 由 FastAPI 显式重定向；旧 hash URL 由 Vue Router 在初始化时解析、映射并
保留股票、市场和来源参数。旧 Jinja/Vanilla 壳已删除，回滚边界由 Git tag、同源 `/app` shell
和 API 兼容契约提供，而不是继续维护第二套前端运行时。

### 10.3 设计原则

- 默认浅色并支持深色/跟随系统；交易研究使用紧凑、可扫描、非营销式布局。
- 报告不是 Dashboard 卡片：它是独立阅读页，移动端优先展示动作、风险、变化和数据状态。
- 所有数据状态显示来源、时间或覆盖范围中的至少两项；数据缺失显示原因，禁止以 0、
  空白图表或模拟数值掩盖。
- 图标按钮使用已有图标库并提供 tooltip；可见文本按钮只用于明确命令。控件保持稳定尺寸，
  关键移动操作目标不小于 44px。

## 11. 兼容、迁移与 API

- 现有 `qlib_*` 和已有 signal 旧字段保留 legacy adapter；新 Decision API 使用明确的
  `decision_*`、`portfolio_*` 和 `report_*` 语义。任何移除必须在兼容期结束后的独立变更中
  完成。
- 现有 `daily_reports` 的 `(workspace_id, trade_date)` 唯一性不能承载“一天多市场、多组合、
  多报告”的业务语义。新报告索引以 `decision_run_id/report_type/portfolio_version_id` 和明确的
  slot 幂等键约束，旧日报表只读迁移或作为 legacy view，不覆盖其行。
- 现有自选股仍按 current workspace 边界读取；新组合成员只引用该 workspace 允许访问的标的。
- 数据库迁移必须前向兼容、幂等、可分批执行。新旧 consumer 不得同时拥有同一 Outbox
  event type；切换需要显式 worker ownership 开关和可观测的 draining 状态。

## 12. 验收标准

### 12.1 领域与复现

- 修改策略、权重、阈值或风险规则后，旧决策仍能显示当时的 `PortfolioVersion`、输入 hash、
  贡献、报告和投递；新运行使用新版本。
- 给定同一输入快照、组合版本和确定性策略版本，重放得到相同动作、综合分、原因码和报告
  hash；AI 不可用不会改变动作。
- 同一股票属于两个组合时，两组决策、报告和通知互不覆盖。

### 12.2 推送与健康

- 无变化的定时报告只发送总览和链接；普通动作第一次建立不发消息；两根完成 5 分钟 K 线
  确认的动作变化仅发一次；首次重大风险立即发一次。
- 通知目标未测试、数据预览为空、验证不足或当前数据失效时，自动开关禁用并说明精确原因；
  手动分析仍然可用。
- Worker 重启、重复调度或外部请求超时不会造成重复成功投递；每一次尝试均可查询。

### 12.3 回测与多市场

- 样本外窗口、成本版本、公司行动、基准、停牌/涨跌停和缺失数据处理可从结果查询。
- 权重候选不能在硬门槛不通过时生效；相同候选输入的选择结果稳定。
- 日韩台在没有合格盘中 adapter 时，任何 UI、API 和调度都不能生成 5 分钟自动推送。

### 12.4 前端与兼容

- 每行功能迁移矩阵都有路由、权限/禁用状态、API 契约测试和至少一个桌面与移动的 Playwright
  关键流程；没有映射的旧功能不得退役。
- `/app/*` 在桌面和 390px 移动视口无横向溢出、无重叠、可完成主要研究和验证流程。
- 已知旧 query/hash 链接能到达等价新页面并保留股票/市场上下文；兼容期内旧页面可以回滚。
- 分享链接在有效期内仅可读其目标报告，过期或撤销返回不可访问，且不泄露 workspace 信息。

## 13. 风险和边界

- 数据、回测和 AI 结论不是投资承诺。所有动作均为研究状态；未来实盘必须额外经过人工
  订单确认、券商权限、风控和独立规格。
- 个人微信第三方服务、机器人平台和 cloudflared 都依赖外部可用性与各自条款。投递成功
  只能说明 provider 接受请求，不等于终端用户已阅读。
- 本机长期运行依赖 Mac 电源、网络、Docker 和隧道；Worker 必须暴露离线、错过 slot、
  追赶执行和最后成功时间，不应隐瞒停机。
- SQLite 适合当前单机、单 Worker 的个人系统；若未来需要多节点、高并发 writer 或跨设备
  主从，须以独立 ADR 评估 PostgreSQL/对象存储迁移，不能隐式横向扩容。

## 14. 发布、回滚和完成定义

发布按实施计划逐阶段启用，初始均为只读或手动模式。自动推送只在 A 股的单个测试组合
通过资格门槛后灰度启用；其它组合、市场和渠道单独打开。任何 provider、LLM、Webhook、
Docker、隧道或真实交易联调均在实施时重新确认影响范围。

回滚优先关闭 worker schedule、自动推送 route 和新 Vue 默认入口；保留已生成的输入、
决策、报告、AI 工件、Outbox 和投递历史。不得通过删除历史 SQLite 记录“回滚”。

本次重构完成的定义不是新增了多少页面或 provider，而是：用户能从自选组合获得可解释、
可验证、可复现的决策；只在恰当时点收到简洁通知；能在链接中阅读完整报告；并且当前
Dashboard 的所有既有能力在新前端有可用、可测试、可回滚的去处。
